## Why

A handoff carries a task, scoped context, and partial results with their confidence.  The failures this list guards against are a payload that drops the confidence or the conflict, and a check that counts one claim twice.

## How to use it

Work from the top.  Close an item only with a test or a document change in the same pull request.  Every bar in this list is a guess until the first real runs measure it (item 6).

## The list

1. **Confidence per parameter.**  Add `confidence` and `confidence_reason` fields to the separate evidence file (`data/parameters/evidence_columns_DRAFT.csv`; the parameter CSV keeps its eight columns, as agreed on 2026-10-26), and make the validator reject empty values.  Owner:  Valerie (data), Anastasiya (validator).  Enforced by:  CODE.  Status:  built for form (the evidence file is on `develop`, #35; the validator rejects a label outside `low`, `medium`, `high` and an empty reason, #47); whether a label is justified stays a human judgment.
2. **Independent origin per source.**  Add an `origin` column to `sources.csv` (the study a source repeats) and a row-level `origin` field to the evidence file, and make the validator count two sources with one origin as one.  Owner:  Valerie (data), Anastasiya (validator).  Enforced by:  CODE.  Status:  partly built (both fields are on `develop`; the validator checks that a row's origins are a subset of the origins of its cited sources, #47).  Not built:  counting distinct origins, and a warning for `high` with one origin.
3. **Contradictions travel in the handoff.**  Add a `contradicts` field to the evidence file that names the parameters or sources in conflict, and move the conflicts from `docs/research-notes.md` into it.  The validator rejects a name that does not exist.  Owner:  Valerie.  Enforced by:  CODE for the references; the Evaluator checks that every conflict in the notes has a link.  Status:  built for the references and the data (on 2026-10-26, 8 of 23 rows record a conflict, 15 say `none_identified`, and none say `not_checked`; #35, #47).  Not built:  the test that holds the known conflicts, and the Evaluator's link check.  A `not_checked` row blocks a final run in the evidence gate (#86, in review).
4. **A hand-back path.**  The Developer or the Evaluator files a typed request to the Researcher (parameter name, what is missing).  The harness allows one round per case, batches every open parameter, and stops and reports to both of us if one stays unresolved.  Open decision:  what happens when the batch exposes a new gap (proposal:  the case stops and reports; it never opens a second round).  Owner:  the pair, at the harness session.  Enforced by:  CODE (one budget counts every request, whoever files it).  Status:  missing (only Evaluator to Developer revision exists, 3 rounds).
5. **The harness computes the content hashes, never an agent.**  Owner:  the pair.  Enforced by:  CODE.  Status:  open decision (`docs/architecture.md`).
6. **Label every bar "guess" or "measured".**  This covers the eval plan, the baseline test, the sandbox limits (300 seconds, 10 MB), the history tolerance (0.05 and 10%), the trial counts (100 and 500), and the audit bar in item 7.  Re-ground each bar in the first real runs, and change a bar only in a commit that says why.  Owner:  Valerie.  Enforced by:  review.  Status:  partly (bars are written first; none is labeled).
7. **Human audit and two new planted flaws.**  Before each experiment batch, a person checks 10 random parameter rows against the primary source (bar:  9 of 10), and the team reads the total across batches, not one batch.  Add two flaws to `docs/baseline-test.md`:  a contradicting source dropped from the table, and two sources with one origin counted as two.  Owner:  Valerie.  Enforced by:  a person, plus the baseline test.  Status:  partly.  The two flaws are flaws 7 and 8 in `docs/baseline-test.md` (since 2026-10-22), with case files built by `scripts/baseline_cases.py`; the audit draw is `scripts/audit_sample.py` (#58, merged); the validator checks structure only, so both flaws pass it.
8. **Count missed contradictions.**  Record in each trace every contradiction the Developer or the Evaluator finds that the table should have flagged.  A rising count means the Researcher misses quietly.  Owner:  Valerie.  Enforced by:  CODE (a trace field).  Status:  missing (`docs/trace-plan.md`).
