# Red team of our own handoffs (DRAFT)

Written 2026-10-29 by Valerie with Claude Code, from LaNice's group exercise of that day, "Team Problem-Solving: Red Teaming Exercise".  The exercise asks a pair to swap systems with another pair, attack handoffs, shared state, and inter-agent trust with malformed input, and report what broke, how it was triggered, and the top fix.  We have no other pair at hand, so this file is the same method turned on our own system:  fourteen scripted attacks, each pinned by a test in `tests/test_red_team_handoffs.py`.  Nothing here is agreed until Anastasiya says yes.

## The answer first

Twelve of the fourteen attacks failed, which is the right result:  nothing that contradicted itself, was malformed, or changed the research files passed.  Two gaps got through, and both are low severity:  results labelled `sample` pass the whole chain, and a spreadsheet formula in a source cell is accepted.  The top fix is to refuse `sample` results in `run_case`.  It is not needed for Friday's runs, because the fixed Developer always returns `simulation`.

Inter-agent trust (the Researcher's text and the code-made issues entering the Developer's task) is covered in `docs/permission-boundaries.md` and `tests/test_permission_boundaries.py`:  no text that crosses a handoff can change what the fixed tools do.

## The two gaps

**1.  Results labelled `sample` pass.**  *Triggered by:*  a Developer that returns valid, matching results with `data_kind` set to `sample`.  *Effect:*  the case ends `pass`, so a hand-written fixture could be shown as a passing case.  The provenance check, which refuses placeholder hashes, applies only to `simulation` results.  *Limit:*  the hashes must still match the input, so the label alone cannot hide a wrong table.  *Top fix:*  in `run_case`, after the results schema check, refuse any `data_kind` other than `simulation` (about three lines and one test), or let it pass only with an explicit flag.  Severity:  low.

**2.  A spreadsheet formula in a source cell is accepted.**  *Triggered by:*  a `sources.csv` cell that starts with `=`.  *Effect:*  none in Python.  Anyone who opens the file in a spreadsheet may run the formula, and the repository is public, so a pull request could carry one.  *Top fix:*  the parameter validator refuses a text cell that starts with `=`, `+`, or `@`.  Severity:  low.

Each gap has a test named `test_known_gap_...`.  When a fix lands, that test changes to expect `rejected`.

## What this does not show

- We attacked our own system, so we share its blind spots.  A swap with another pair would find what we cannot.  The repository is public, so offering it to a pair is possible.
- The attacks were scripted and offline.  No live model played the attacker, and one live pass has run.
- Not tried:  concurrent writers, very large inputs, symbolic links, and paths in the output folder name.
